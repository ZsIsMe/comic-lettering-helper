# 預排版匯入

在本專案根目錄執行 `scripts/import_prelayout.py`，透過正式 6008 API 匯入；不直接讀寫伺服器項目檔、不以瀏覽器逐個點選匯入。

## 輸入

- `image_dir`：必填，圖片資料夾。只匯入第一層 PNG／JPG／JPEG，按自然順序排列並忽略 `._*`。
- `--translation FILE`：可選，一份含 `transMap` 的 JSON 或 LabelPlus TXT。未指定時只建立項目及完成 OCR，不自行搜尋譯稿、不翻譯或新增 OCR 原文文字框。
- `--name NAME`：可選。優先採用使用者指定名稱；可從本次明確的作品／章節推得，例如「選秀王8」。未提供時腳本使用圖片資料夾名稱。

相對檔案路徑以呼叫時的工作目錄解析。多個圖片資料夾分別執行、串行完成，各自建立獨立項目。譯稿須明確對應該資料夾，不能將同名的不同章譯稿交叉套用。

## 操作

使用專案 `.venv/bin/python`。先檢查服務；未啟動且本機環境已設定時，用既有 `./scripts/start-local.sh --no-open` 啟動，不自行啟動另一份後端。

```bash
.venv/bin/python scripts/import_prelayout.py "/圖片資料夾" \
  --translation "/譯稿/labelplus_output_NEW.json" --name "作品第8話"
```

只要求分析時，加 `--check-only`：檢查本機輸入及服務可用性，不建立項目。一般執行會先驗證圖片、頁名與譯文，再建立項目，使用既有 `ocr_aligned`（預設字級 24、步長 2）完成 OCR，接著匯入譯稿、預覽並套用匹配，最後讀回核對。缺少譯稿的圖片頁保留空白文字並列入報告；未知譯稿頁名、多對一頁面或格式錯誤必須先處理。

JSON 保留原文字元、空白、換行及附加資訊。TXT 沿用 LabelPlus 結構；每個文字區塊最後一個換行作為格式分隔，其餘文字空白／空行保留。若既有 TXT 匯入器會壓縮文字空白／空行，腳本透過 BT JSON 轉接保留，報告列出 `import_kind`；頁面之間的分隔空行無法可靠歸屬時，在匯入前報錯，不猜內容。純文字 TXT 不支援。

## 續作與回報

續作紀錄預設放在專案忽略目錄 `var/prelayout-imports/`，不寫入來源資料夾。相同命令保留相同參數執行，沿用紀錄中的項目；完成後重跑只核驗。`--state-file PATH` 僅供明確指定另一份續作紀錄，不能為繞過錯誤而自動換紀錄、重建項目。

OCR 超時或使用者中斷不代表後台工作取消，先查看同一紀錄和項目。寫入結果不明時不得盲目重送；保留錯誤、紀錄位置及已知項目 ID，核對正式 API 狀態。項目修訂已被其他操作更動時停止，不能用新修訂強行覆蓋。來源檔案改動亦須先核對。

回報項目名稱／ID、頁數、文字數、OCR 狀態、文字完整性及 `auto`／`unmatched`／`duplicate` 數量，並提供紀錄位置。未匹配、重複匹配需後續看圖校對；本 Skill 不標記人工校對完成，不修字或調整人工排版。只有使用者另行要求查看時才開瀏覽器，並保留已存在的分頁。
