# 6008 網頁更新與計時驗收（2026-09-13）

## 實際版本升級

- 0.2.1 沒有安裝器，因此先以管理通道部署一次 0.2.2 安裝器基線；這一步不計為網頁升級驗收。
- 隨後所有升級操作均在 6008 網頁進行：檢查更新 → 顯示 0.2.3 → 立即升級 → 保存並升級。
- 瀏覽器透過既有 SSH 埠轉發存取同一個 6008 HTTP 服務；轉發僅提供連線，沒有用 SSH 指令執行此次 0.2.2 → 0.2.3 升級。
- 獨立安裝器從 GitHub Release 下載 application.zip 和校驗碼，校驗、備份、安裝、重啟，約 8.08 秒完成。
- 網頁自動重新載入，顯示「應用版本 0.2.3」及「更新完成，網頁已恢復」。
- 只讀驗證 update-status：previous_version=0.2.2、version=0.2.3、state=completed。
- deployed-release.json 記錄 method=6008 web updater、commit=eccbba0bdae9022e395de8b0e97323ea40f06ec9；79 個更新檔案 SHA-256 全部吻合。
- 健康接口 app=ok、active_job_id=null、gpu_owner=null；ComfyUI 沒有啟動。修圖、預排版與 jobs 清單保持空白。

## 計時驗收

使用本機隔離 HTTP 測試資料與正式前端構建；沒有呼叫模型或 ComfyUI。

- 模擬 running 任務：網頁「已運行」從 35 秒增加至 1 分 0 秒。
- 將模擬任務設為 completed 並保存 finished_at：網頁固定「總耗時 1 分 8 秒」。
- 刷新並返回批量修復頁後，仍為「總耗時 1 分 8 秒」。
- 單元測試額外覆蓋 failed／abandoned 停表、刷新恢復、後續 metadata 更新不改變 finished_at，以及舊紀錄相容。

## 自動檢查與界線

- 前端 lint、build、65 項前端測試通過。
- 208 項後端測試通過。
- 安裝器測試覆蓋不允許的路徑、包損壞、環境需求不符、下載失敗不重啟、更新與保存／任務互斥、跨站要求拒絕。
- 新版重啟失敗後回復舊版在隔離測試中驗證，保留使用者資料；未刻意破壞遠端服務測試回復。
- 未執行 GPU 推理，不能將此次網頁更新驗收視為模型或新鏡像 CUDA 驗收。
