## 1. 需求基線與整合範圍

在現有漫畫修圖程式內增加「預排版」功能，使用同一工程與既有 React、TypeScript、FastAPI、6008 網頁服務。預排版有獨立入口、項目清單與編輯狀態，可直接使用，不需要先執行圖片修復。

依使用者撤回的討論範圍，獨立倉庫與桌面端應用打包不納入本計劃，也不列為後續階段或待決事項。

| 已確認要求 | 實作約束 |
| --- | --- |
| 預排版與圖片修復不共用資料 | 分開上傳圖片、建立項目、保存進度、生成快取與輸出；不引用修圖項目的資產、Mask、候選結果或修訂 |
| 參考既有預排版工程 | 參考 `/Users/zhongsheng/Projects/comic-text-detector`，整理必要處理核心；部署後不依賴此本機路徑 |
| 不需要測量角度 | 不移植獨立角度測量視窗、單字選區測量與測量套用流程；保留一般文字框旋轉 |
| 不需要編輯 `measure.json` | 後端可以生成、讀取量測資料，用於匹配、字級與唯讀對照；不提供人工修改 measure 的介面或 API |
| 重新設計網頁介面 | 按浏览器連續閱讀、選取與編輯流程組織工具，不照搬舊 Qt 視窗 |
| 漫畫頁連續上下捲動 | 多頁依序排列在同一主捲動區，能自然跨頁；頁碼跳轉是輔助操作 |
| 移動、旋轉、縮放與捲動流暢 | 優先建立互動效能基線，再接入完整模型流程；普通文字操作在瀏覽器即時完成 |
| 允許底圖模糊預覽 | 使用較低解析度的圖片副本；原圖、排版座標與匯出資料保留原本精度 |
| 模型不放進工程 | 權重、模型快取與推理環境留在工程外，README 記錄所需資產和鏡像安裝方式 |

既有修圖三部分、歷史批次、資料格式及三套正式工作流維持原有責任。預排版中的 `need_inpaint` 等既有欄位只作排版資料保存，不連動修圖任務、不生成交給修圖的輸入。

本文中預覽級別、快取上限、API 名稱及效能門檻屬於實作初始方案，允許依量測調整，但不能犧牲資料隔離、編輯精度或連續捲動要求。

## 2. 參考工程與移植邊界

### 2.1 已確認的程式來源

參考工程檢視基線為 commit `ffa7b7e`，檢視時受追蹤檔案沒有本機修改；目前發行工程基線為 `ad7bfc0`。正式移植時仍應記錄完整來源 commit、實際抽取檔案及必要修正。

| 參考模組 | 用途與處理方式 |
| --- | --- |
| `ctd_overlay_processor/run_detection.py`、`new_detect_folder.py` | 抽取 CTD 偵測、對齊、量測的必要步驟；去除對母工程工作目錄和 `sys.path` 的依賴 |
| `建立对齐方框/` | 整理實際被引用的對齊演算法與資料結構，按依賴逐項遷入 |
| `ctd_overlay_processor/processor.py`、`analyze_text_core.py` | 讀取框資料、方向、顏色與描邊等結果，整理為不依賴 Qt 的核心 |
| `measure_ocr.py`、`mit48px_ocr.py`、`font_size_calibration.py` | 保留 OCR 對齊字級計算和必要模型適配，外置模型、字表、字型及墨跡指標路徑 |
| `lp_to_meo.py`、`build_text_rect_update.py`、`labelplus_pipeline.py` | 保留 LabelPlus 解析、分組、匹配、MEO／BT 輸出語意 |
| `viewer_bt_*`、`viewer_popovers.py` | 參考欄位、互動語意與直排規則；文字渲染及互動以瀏覽器重新實作 |
| `measure_editor.py`、`bt_measurement_dialog.py` | 不移植指定排除的人工量測與 measure 編輯功能 |

來源檔案可能混合多種責任，例如 `viewer_bt_measurement_mixin.py` 也含一般字級和旋轉預覽邏輯，應按功能抽取，不按檔名整包搬入。保留實際移植程式的來源與授權說明。

### 2.2 避免帶入無關流程

現行 `run_detection.py` 會呼叫 `only_text`／`inpainted` 圖片輸出。網頁預排版抽取偵測、對齊、量測與匹配步驟，並依後續需求接入來源 `_write_inpainted_images` 的 OpenCV Telea 預覽（radius 3、mask expansion 5）。其 RGBA 輸出是透明覆蓋層，須疊回原图生成完整底圖；不直接執行整個 GUI 包裝器或三套修圖工作流，沒有修圖資料交接。

舊程式已有底圖快取，但 HTML 文字更新仍涉及 Qt／WebEngine 同步、批量樣式更新及元素尺寸讀取。這些是效能檢查方向，尚無 profiling 證據證明某一項是舊程式卡頓的唯一原因。

## 3. 使用者流程與第一版功能

### 3.1 入口與資料準備

```text
程式入口 → 預排版項目列表 → 新建／重開預排版項目
                              │
                         上傳原圖（必須）
                              │
          ┌───────────────────┼────────────────────┐
          ▼                   ▼                    ▼
    生成 CTD／量測資料    開啟既有 _bt.json      手工建立文字框
          │                   │                    │
    匯入 LabelPlus txt        │                    │
          │                   │                    │
    自動匹配與初步排版 ────────┴────────────────────┘
                              │
                     連續多頁預覽與人工編輯
                              │
                   保存進度／匯出 _bt.json
```

- 新建項目包含名稱及原圖；支持圖片多選和資料夾第一層，忽略 `._*`，按自然順序排列。
- 偵測後自動使用生成的 `inpainted` 預覽，不必先上傳去字圖；全批完整、尺寸正確後才發布。仍可另行上傳同頁去字圖，以明確頁名配對，stem 備援必須唯一；不能按上傳順序錯配或靜默拉伸。
- 開啟既有 `_bt.json` 不強制重新偵測。第一版可經程式生成量測資料；外部整套 CTD 資料的任意格式匯入不作前置需求。
- LabelPlus 匯入先顯示頁面對應、分組與條目數。原工程預設的框外分組另存規則必須清楚呈現，不把這些文字靜默丟棄。
- 有量測資料時執行既有匹配；沒有量測資料時仍可保留 LabelPlus 原始位置，以明確預設字級建立待匹配草稿，標示尚未匹配，不虛構自動匹配結果。
- 主頁列出預排版項目、頁數、更新時間與目前狀態，支持重開、改名、下載及有明確目標的刪除。

### 3.2 網頁編輯器

- 頂部常用工具固定可見；左側縮圖／頁碼導航；中央為連續漫畫頁；右側為目前選取文字的屬性及條目列表。窄視窗收合側欄，保留主捲動區。
- 支持點選、拖動、調整框大小、旋轉、鍵盤微移、新增、複製、刪除、撤銷及重做。
- 沿用舊程式的移動 1／10／50 px、字級 2／10、旋轉 1°／5° 快捷鍵與 Option／Alt 滾輪調字級，多選逐條相對調整，長按可一次撤銷；普通滾輪仍上下捲動。
- 選框四角提供逆時針／順時針旋轉按鈕，點擊 1°、Option／Alt 點擊 5°；保持固定螢幕大小，點擊不觸發拖動。上方拖曳旋轉點保留。
- 支持文字內容、顯式換行、字級、橫排／直排、文字色、描邊色與粗細；保留舊資料的修復／描邊標記，但不触發圖片修復。
- 支持 `auto`、`duplicate`、`unmatched`、`manual` 匹配狀態與待處理條目跳轉。手動選擇唯讀偵測框時，把必要框、中心、字級、方向和樣式套用到 BT 條目，量測資料本身不改動。
- 保留文字框暫存複製／貼上與預排版專用的常用文字框列表；暫存內容與持久列表分開，列表不讀取修圖資料。多選及批量字級調整放在基本互動流暢後完成。
- 原圖／去字預覽可以切換；缺少去字圖時標示實際底圖。對照模式按頁左右配對、使用同一垂直捲動軸和縮放比例，不建立兩個易失同步的長捲動區。
- 初始按圖片寬度縮放；頁码跳轉、選取、工具列操作不重置已有縮放。捲動位置以頁 ID＋頁內偏移保存，不能只保存易受預覽高度影響的全頁像素值。

### 3.3 保存與輸出

依後續需求，排版輸出只提供 `bt.json`；移除「導出項目」及項目 ZIP 匯出 API。原圖、已保存文字、必要量測與來源對應留在伺服器專用項目中，關閉網頁後可重新開啟續編。既有預排版封存仍可匯入；成品文字烘焙圖片、PDF 與其他排版軟體格式轉換不在本次輸出內。

刷新、跨頁、模型任務完成或預覽清晰度切換都不能清除已保存編輯。瀏覽器離開、切換模組前處理尚未保存修改；保存失敗時顯示狀態並保留草稿，不能顯示為已保存。

## 4. 資料隔離與資料契約

### 4.1 隔離範圍

已新增 `COMIC_PRELAYOUT_DATA_ROOT`，預設為 `<COMIC_DATA_ROOT>/prelayout`，與現有 `<COMIC_DATA_ROOT>/projects`、`jobs` 平行。名稱相同或圖片內容相同也建立預排版自己的資產，不跨功能使用符號連結、硬連結或內容去重引用。

```text
<COMIC_PRELAYOUT_DATA_ROOT>/
├─ projects/<prelayout-project-id>/
│  ├─ project.json                  格式版本、頁面索引及各資產修訂
│  ├─ originals/                    原始上傳，保持原件
│  ├─ clean/                        已發布的 inpainted 完整底圖或另外上傳的去字圖
│  ├─ imports/                      原始 LabelPlus／BT 資料
│  ├─ pages/<page-id>/               當頁草稿、修訂與條目 ID 對照
│  ├─ detections/<detection-id>/     不可變输入索引、CTD／OCR 產物
│  └─ previews/                     可重建的縮圖、分級預覽與局部圖塊
└─ preferences/                    預排版常用文字框等持久偏好
```

預排版列表與 API 只查詢自己的儲存區。修圖的封存、匯入與刪除同樣不得包含預排版目錄。預排版不再提供封存匯出；匯入既有封存時只接受其原圖、可選去字圖、匯入稿、已保存文字及必要量測資料，重新分配新 ID，所有引用改為封存內的相對資產。

### 4.2 圖片與文字座標

- 每頁有穩定 ID、原始檔名、排序、像素尺寸及內容雜湊。先取得尺寸再安排頁面高度，預覽切換不改變頁面幾何。
- 文字座標始終以該頁原圖為基準，預覽級別與裝置像素比只影響顯示。Pointer 座標經頁面偏移、縮放與旋轉的逆變換轉回原圖座標。
- 用浮點數保留互動位置，避免每次移動反覆四捨五入。匯出時按既有 BT 契約一次規範化；測試中心、框與 `x/y` 是否一致。
- 正式搬入既有 `rotation` 方向語意，注意原 HTML 顯示使用負號；以已知正負角度的測試資料驗證，不憑視覺猜測。
- 圖片 EXIF 方向必須在匯入時確定。已有 BT 的圖片不可單獨自動旋轉；無法證明座標一致時先報出問題，不靜默改圖。
- 內部條目使用穩定 ID，與可重排的陣列位置／舊 `index` 分開。匯入保留未知欄位，匯出移除內部管理欄位並保留原有頂層與分組資料。

### 4.3 草稿、修訂與並行操作

- 每頁保存帶 `expected_revision`、操作 ID 和變更；資產先寫臨時檔，再原子替換並更新索引。單次請求成功前不切換正式修訂。
- 一次拖動或旋轉作為一個撤銷步驟；Pointer 移動只改暫存互動狀態，Pointer 結束後提交一次差異。鍵盤連續操作按短暫停頓合併，保留最終值。
- 自動保存採約 500～1,000 ms 停頓合併；手動保存與導出立即排程並等待確認。請求依序提交，避免舊回覆覆盖新狀態；失敗時保留可重試操作。
- 瀏覽器持久草稿使用預排版專用儲存鍵，記錄伺服器修訂；重開遇到版本不同時保留兩份並顯示衝突，不自動覆蓋。
- 重新偵測建立新的量測版本，不直接覆蓋 BT。重新匹配先產生候選變更，人工修改的條目只在明確選取套用時更新。
- 頁面離開可視區時先把編輯狀態交回資料層，卸載的僅是畫面節點，不能連草稿一起卸載。正在拖曳、輸入或有焦點的頁暫時保留。

## 5. 流暢性與圖片預覽設計

### 5.1 連續頁面與有界快取

採用虛擬化頁面列表：視覺上整章連續存在，實際掛載可視頁及前後緩衝頁，其他頁保留已知比例的空間。初始緩衝為可視範圍前後各約一個視窗，再依速度與量測調整。縮圖亦需延遲解碼，不能預先解碼整章原圖。

圖片、圖塊與文字節點均設上限。圖片快取以估計解碼像素量計算，而不是只看 JPG／WebP 檔案大小；起始瀏覽器圖片快取預算 256 MiB，包含原圖預覽和對照底圖。離開範圍按 LRU 釋放圖片引用、Object URL、ImageBitmap／Canvas 資源。總程序記憶體另行量測，不能把此預算稱為瀏覽器總用量。

### 5.2 分級預覽

| 情境 | 底圖策略 | 文字與互動 |
| --- | --- | --- |
| 初次進入／快速捲動 | 優先顯示已快取的小預覽，按捲動方向預取 | 可視頁文字保持可讀；不等待高清載入 |
| 一般預排版 | 使用符合顯示尺寸的中等解析度副本 | 文字和選框以獨立圖層顯示 |
| 移動／旋轉文字 | 保持目前已解碼底圖，避免在操作中切換清晰度 | 只更新選中物件變換，即時跟隨指標 |
| 縮放中 | 先變換既有底圖及文字 | 以指標位置作縮放錨點，避免跳位 |
| 縮放停止／查看細節 | 延後約 200～300 ms 請求更合適級別；大圖只取可見區圖塊 | 清晰度切換沿用同一座標及縮放 |

初始預覽可用長邊 768／1,536／3,072 px 的等比例版本，小於原圖時才生成；超出級別的細節使用受限制大小的局部圖塊。圖塊以原圖座標定位，邊界留重疊避免縮放接縫。級別選擇考慮顯示尺寸、裝置像素比及快取預算，切換加遲滯，避免在臨界縮放來回請求。

降低解析度只作用於預覽副本，不改原圖。單純對原尺寸圖片加模糊濾鏡不能達到相同的解碼記憶體節省，初版不用模糊濾鏡。預覽格式以解碼耗時、體積與文字底圖辨識度實測選擇，不先追求最高壓縮率。

### 5.3 文字渲染與互動路徑

優先使用圖片底層＋HTML 文字層＋選框互動層。HTML 負責橫豎排、字型和標點，選框可用 SVG；第一版避免自行以逐字 Canvas 重建所有直排排版規則。

1. `pointerdown` 固定選取、原始座標與旋轉中心，建立 Pointer capture 及互動快照。
2. `pointermove` 只更新最新指標值，透過 `requestAnimationFrame` 每畫面最多更新一次選取物件的 `transform`。不在每次事件更新整章 React state、重新計算所有文字或呼叫遠端。
3. 移動／旋轉過程不重新量字、不重設字級，不反覆讀取 `offsetWidth`／`getBoundingClientRect`。文字、字型、方向或換行改變時才重新量測，將讀取與寫入分階段完成。
4. `pointerup` 套用精確結果到資料層、記錄撤銷，並安排非阻塞保存。`pointercancel` 回復互動前狀態，釋放頁面保留與 Pointer capture。
5. 有選取時僅為活動物件保留必要合成資源；結束後清理。避免替整章所有文字長期啟用 `will-change`。

文字描邊、直排標點和混排需獨立驗證。舊版使用多重 `text-shadow` 的做法不直接照搬；先比較原生描邊和快取方案的外觀與成本。若需把複雜文字暫存為貼圖，只能在樣式改變時建立，移動／旋轉使用既有貼圖，不在每幀重新排版。字型載入完成前不能提交依據臨時替代字型算出的正式位置。

### 5.4 效能目標與量測方法

以下為持續採用的驗收門檻，本機已以桌面 Chrome、固定字型及暖快取建立基線，完整條件與實測值見驗證記錄。記錄機型、瀏覽器版本、裝置像素比、圖片尺寸、每頁文字數與對照模式，不用未說明環境的單一 FPS 宣称全面流暢。

| 項目 | 初始目標 |
| --- | --- |
| 拖曳／連續旋轉 | 以接近 60 fps 為目標；暖快取下連續 10 秒操作，P95 幀間隔不超過 20 ms；以 trace 區分 JS／layout／paint 成本 |
| 操作回應 | 暖快取下 pointer 到下一次可見更新 P95 不超過 50 ms；rAF 僅作代理量測，配合瀏覽器 trace 確认呈現 |
| 保存及高清圖片載入 | 注入 500 ms API 延遲時，拖曳／旋轉仍在本機回應；不等待網路回覆才更新畫面 |
| 長章節 | 100 頁、每頁約 30～50 個文字框的測試集；掛載頁數、DOM 與圖片快取受可視範圍和預算限制 |
| 冷載入與快速捲動 | 可短暫保留低解析度圖片；不跳動頁高、不回到頁首、不讓圖片解碼長時間阻塞文字操作 |
| 精度 | 預覽級別、50%／100%／200% 縮放、跨頁再返回及匯出往返，中心偏差不超過 1 原圖像素；未修改條目不累積漂移 |
| 長時間使用 | 同一路徑上下捲動三輪後資源量回到既定快取範圍附近，不隨已看過頁數持續累積 |

測試資料包含 2,000～4,000 px 寬的普通漫畫頁、一張至少 8,000 px 長邊圖片、密集文字／粗描邊頁，以及單張超長圖。測試集優先使用合成資料及使用者指定資料，使用者圖片和 profiling 產物不進 Git。門檻未達時記錄瓶頸並修正，不以模型已接通替代互動驗收。

## 6. 偵測、字級與模型部署

### 6.1 處理流程

```text
驗證原圖與執行環境 → 固定輸入清單 → CTD 文字偵測
                                           │
                                     對齊與量測資料
                                           │
                      ┌────────────────────┴───────────────────┐
                      ▼                                        ▼
              OCR 對齊逐字計算                           單字框計算
              mit48＋可靠字元校準                        不執行 mit48 OCR
                      └────────────────────┬───────────────────┘
                                           ▼
                               保存本次唯讀量測版本
                                           ▼
                                匹配候選 → 套用到 BT
```

- 保留原工程兩種字級方法，預設「OCR 對齊逐字計算」。缺少 OCR 模型時明示該方法不可用，不能靜默切換到另一種方法。
- 字級校準初始參數沿用 `default_font_size=24.0`、`step=2.0`，量測結果保留一位小數；BT 匹配時的字級量化另沿用原邏輯，不把兩種 step 混為一談。
- 保留唯一匹配、重複匹配、未匹配及鄰近樣式繼承的既有規則，先用代表性資料建立前後對照，再調整必要的檔案存取與介面。
- 不重新翻譯譯文；OCR 只服務既有量測及字級流程。人工修改 BT 不觸發偵測或 OCR。
- 字級、方向、顏色分析所需資料留在預排版自己的偵測版本內；推理結果先完整驗證再發布。失敗保留前一成功版本和已保存文字。

### 6.2 模型與配套資產

模型資訊集中補充在專案 [README](../README.md) 的預排版區塊，不把權重或模型快取放入工程，也不要求使用者先放進工程再搬到鏡像。不因缺檔自動下載大型模型。

鏡像模型根目錄預設 `/root/models/comic-prelayout`，位於程式原始碼目錄之外。`COMIC_PRELAYOUT_MODEL_ROOT` 已接入服務與推理子程序。

| 資產 | 參考工程已知名稱 | 用途 |
| --- | --- | --- |
| CTD 權重 | `comictextdetector.pt` | 文字框、文字行及遮罩偵測 |
| mit48px CTC 權重 | `mit48pxctc_ocr.ckpt` | OCR 對齊字級計算 |
| OCR 字表 | `alphabet-all-v5.txt` | 與 OCR checkpoint 配套，不能任意替換 |
| 校準字型 | `NotoSansCJKjp-Medium.otf` | 字級墨跡量測的基準字型 |
| 字型墨跡指標 | `NotoSansCJKjp-Medium.ink-metrics.json` | 必須與校準字型雜湊一致 |

上述五项資產已讀取參考工程現有檔案核對 SHA-256，並完成本機核心依賴／字型指標預檢；没有把資產複製進工程或下載模型。README 記錄實際來源路徑、雜湊、觀察到的依賴版本及目標 CUDA 尚未驗收的限制。

推理使用鏡像內外置的 Python 環境，由 `COMIC_PRELAYOUT_PYTHON` 指定；Torch、OCR 等重依賴延遲載入到子程序。Web 服務啟動和普通編輯不依賴模型或 Qt／QtWebEngine。先檢查可與既有隔離推理環境共存的依賴，不能直接修改 ComfyUI 環境來滿足新功能。

校準字型與編輯預覽字型分清用途。網頁應固定並記錄實際使用的預覽字型版本，經同源字型資產端點載入；來源無法提供或尚未載入時顯示狀態，避免不同電腦的系統替代字型導致字框尺寸不一致。所用字型及字表的部署位置與來源一併記入 README。

### 6.3 GPU 與任務生命週期

共用硬體使用鎖是同機資源協調，不是共用修圖資料。預排版只以自己的任務 ID 申請既有 `manager.gpu_gate`，不建立修圖 `JobRecord`，也不把 CTD 結果寫入修圖項目。

- GPU 忙碌時只拒絕新預排版推理，提供忙碌提示；已開啟的文字編輯、預览與保存繼續運作。普通 CPU 準備工作限制並行度，避免打包／預覽生成阻塞 Web 執行緒。
- 提交偵測先保留 GPU，將輸入索引與任務狀態落盤；沿用既有外部 ComfyUI 任務檢查與必要的閒置模型卸載流程，不重啟 ComfyUI 釋放顯存。
- 目標鏡像優先按 CUDA 路徑驗收，無可用 CUDA 時明確報告；不把本機 CPU 通過當成鏡像 GPU 通過。
- 本地測試允許引用工程外已有模型、配套資產及隔離 Python，使用使用者提供的漫畫資料夾副本。Apple Silicon 明確設定 `COMIC_PRELAYOUT_DEVICE=mps`，不自動選設備或回退 CPU；保留 GPU gate，但不聯絡 CUDA ComfyUI。MPS 實測與目標 CUDA 驗收分別記錄。
- 全批 CTD 完成後再進入所需 OCR 階段，減少模型反覆冷載入；模型交接以子程序退出和显存釋放確認。
- 任務狀態使用 `queued → validating → detecting → aligning → measuring → calibrating → publishing → completed`；失敗或取消保存日誌與已完成階段，發布前不改正式量測版本。
- 取消時等待子程序真正退出後才釋放 GPU。Web 重啟先核對仍存活的子程序與任務，再恢復鎖狀態；不能在未知狀態下重跑模型或釋放鎖。多個管理器的啟動恢復需集中協調，不能各自搶同一把鎖後忽略衝突。
- 固定原圖後推理與文字編輯可並存，推理完成只通知有新量測版本；不自動重排使用者正在編輯的文字。

| 方法與路徑（前綴省略） | 職責 |
| --- | --- |
