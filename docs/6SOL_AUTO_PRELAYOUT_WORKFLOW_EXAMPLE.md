# 漫畫預排版實際操作流程：一個任務紀錄

來源：[Codex 任務 `01a0d230-60bd-7b20-9911-723efd215d87`](codex://threads/01a0d230-60bd-7b20-9911-723efd215d87) 的後段操作紀錄，重點是主代理直接處理 39–70、71–198 頁的做法。這是**已發生操作的摘要**，不是對所有頁面成品品質的獨立驗證；具體標準仍以 [6Sol 操作注意事項](./6SOL_AUTO_PRELAYOUT_NOTES.md)及當前 Skill 為準。

## 操作方式如何改變

早期曾讓子代理處理並依其文字報告驗收，後來發現超框和過長尾列仍被漏掉。該任務改為目前主代理直接在 Codex 內建瀏覽器看原圖、操作工作台、檢查修改後畫面。資料檢查和工具提示用於定位、修改與完整性核對，不代替視覺判斷。

## 後段實際使用的逐頁循環

1. **建立本輪上下文**：確認 6008 工作台的項目、處理範圍、目前頁、未保存狀態與頁面修訂；備份指定頁的處理前資料。開啟較寬的比較畫布並調整縮放，從實際截圖確認文字及氣泡邊界清晰。
2. **取得當頁定位資料**：讀取頁號、頁面 ID、最新 token，以及譯文框 ID、文字、字級、座標、方向、角度和樣式。只回傳操作需要的欄位，避免反覆輸出整頁 JSON。頁號是下一步操作的防錯檢查，資料本身不判定排版合格。
3. **看譯文與原圖**：先從整頁找分鏡及文字區域，再看譯文預覽；在同一頁平移到原圖截圖，確認每框對應的原文及主字大小、位置和畫面層次，再回到譯文。必要時局部放大，特別看氣泡弧線、上下緣、框外字及音效。
4. **同頁集中修改**：先按原圖判斷字級與方向，再處理換行、位置、顏色和描邊。使用 WebMCP 的 `prelayout_patch_page` 以當前 token 和文字 ID 批次修改。工具不適合的正式操作，例如拆開混合字級的框或修正原位編輯文字，使用工作台 UI。
5. **重看渲染結果**：補丁後回到譯文畫面截圖，檢查受影響框及鄰近邊界；仍貼線或溢出就再調。紀錄中的第 122 頁在首輪修改後，又調整換行以補足氣泡下緣留白。已確認且未再受影響的區域不必重複截圖，但每個文字區域至少要看清一次。
6. **保存與翻頁**：全部通過目視驗收才以 `prelayout_save_page` 標記 `reviewed:true`。有重複文字或內容錯亂等未決問題時，可保存現況但保持 `reviewed:false`。再用明確的頁面 ID 導航，重新核對目前頁號；該任務曾遇到連續畫布把「當前頁」判成上一頁。

## 具體例外與收尾

- 第 58 頁的文字含有異常的字面 `\n`，先保留待處理；取得後續指示後，用正式 UI 修成換行，看圖確認後才標完成。
- 第 70 頁用工作台的正式分割功能，將需要不同字級的文字分框，並核對分割後文字的閱讀順序。
- 第 128、152 頁的疑似重複文字，以及第 197 頁的版權頁文字錯亂，保存現況但未標完成，等待使用者決定內容修改。
- 收尾時將文字去除換行後與基線比對；分割框按閱讀順序合併後比對，另查完成狀態及範圍外頁面是否變更。這些是資料完整性檢查，不能證明氣泡內的字級、留白和位置正確。
