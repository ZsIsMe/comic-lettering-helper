# 給 GPT-6 Sol 的漫畫預排版操作注意事項

下次處理 6008 工作台的漫畫預排版前，先讀本文件、[一次實際操作流程的紀錄](./6SOL_AUTO_PRELAYOUT_WORKFLOW_EXAMPLE.md)與 [`auto-prelayout` Skill](/Users/zhongsheng/.codex/skills/auto-prelayout/SKILL.md)。以使用者當次指定的作品、頁數、是否允許修改為準。漫畫看圖、校對與修改由目前主代理在 Codex 內建瀏覽器直接完成，不委派子代理。

## 先弄清資料的角色

- **原圖**：判斷文字對應位置、閱讀順序、主字大小、方向、角度和畫面層次的依據。
- **去字圖**：檢查譯文實際落點、氣泡邊界、背景對比和留白的底圖。去字造成的畫面缺損不屬於排版修復。
- **有問題的 JSON／譯文預覽**：待校對、待修復的草稿。JSON 的文字、ID、座標和修訂號可用來定位及核對修改；它本身不是「排版正確」的證據。

`risks: []`、`rendered: true`、沒有警報、儲存成功、已標完成，以及文字內容完整性檢查，都不能證明畫面合格。不要把讀取 JSON、跑檢查工具或瀏覽縮圖描述成「逐框目視驗收」。

## 開始前先確認畫面真的看得清

1. 確認項目、頁號、頁數範圍、原圖與去字圖都對應正確。觀察**實際畫布截圖與有效尺寸**；全螢幕狀態本身不代表可讀。
2. 整頁縮圖只用來辨識分鏡、文字區域與整體節奏。若左右並排使每頁只剩約 600 px 寬，必須放大、平移，或在同一有效縮放下切換原圖與譯文預覽。每個氣泡及其周圍邊界都要能看清。
3. 改變視窗、側欄、縮放或畫布位置後，重新確認可見尺寸與截圖。看不清就停止下結論，不猜測。

## 每頁必做的視覺校對

### 2026-09-27 固定試排流程

撤回「更積極拆分」的泛化要求。拆框用於分開不同氣泡中被誤合併的文字，不因同一氣泡內文字較長、難以放入或想縮短欄高而拆框。其他拆框需求須有原圖明確的獨立文字層次依據，不能自行擴大授權。同一氣泡原有多框也須視為整句，統一字級、方向、欄距與視覺居中；語意換行不得孤立拉長音及其後標點（例如「——！？」）。

先選擇能讀清主字與氣泡邊界的視圖，按氣泡讀清整句與原文結構，再修改並驗收。可沿用同一縮放，只有文字、邊界讀不清或區域不可見時才放大或捲動，不固定縮小、放大再縮回。工具支援批次提交不代表要一次決定整頁排版；不可省略逐氣泡的判讀與驗收。

拆框須用正式工具，按閱讀順序重組並核對非換行字元完全一致。分別記錄正常排字頁、空白跳過頁、無文字插圖頁與局部待確認頁。品質以實際渲染驗收及後續返修為準；沒有可靠 token 資料及可比較頁面難度時，不宣稱節省用量比例。

支援新版 WebMCP 時，以 `prelayout_set_view` 的 `mode:"overlay"`、`comparison:false` 作為判讀、修改及驗收的預設畫面，利用彩色原字與譯文字形直接比較位置、字級、方向和留白；不例行切原圖或關閉高亮。讀不清先放大局部；使用者指定不切原圖的測試期間，仍無法判斷則保留疑點。高亮顏色與透明度可同次設定 `difference_color`、`difference_opacity`，之後沿用。`original`／`final` 模式仍可供使用者手動檢視，切換保留單頁／並排設定、縮放及捲動位置。

按「**逐氣泡判讀 → 修正 → 查看受影響區域及鄰域**」執行，利用已看清的頁面上下文檢查整體關係；沒有修改的頁面也要逐框看圖。每個文字框，包括框外對白與音效，至少確認：

- 是否有**唯一、正確的原圖對應處**，位置與閱讀順序是否正確；相同文字不一定是重複框。
- 橫排／直排、角度、主字級是否貼近原圖。比較字級時用相同有效縮放，忽略原文注音；不要為了塞進氣泡就任意縮小字。
- 換行是否符合語意、原圖行列形狀和氣泡可用空間；不能只數字數，還要看標點、英文及實際字形。
- **所有字、標點、描邊的四周**是否有清楚留白；尤其檢查氣泡上下端、弧線、尾巴、相鄰人物和分鏡線。偵測矩形不是氣泡邊界。文字「還能讀」不等於排版合格。
- 顏色、描邊、背景對比是否合理；修改大小、位置或角度後要再看一次。

須檢查氣泡間比例、閱讀節奏及框外文字；只有修改影響整體關係或影響範圍不明，才補看全頁。已驗收且未受影響的區域不重截，不以固定截圖上限犧牲可讀性。第 20 頁的教訓是，先前依賴縮圖與 JSON 的檢查漏掉右上氣泡末端擁擠、下方中間對白越出氣泡等明顯問題；必須在可讀的局部畫面逐一確認。

## 修改與完成門檻

- 只修改有清楚原圖依據的排版問題。一般排版僅改換行、大小、位置、方向、角度、顏色及描邊；保留原有字元、空格、標點和閱讀順序。翻譯改寫、刪除疑似重複框等內容變更，按使用者已有的具體授權處理；未授權的歧義列待確認。
- 局部文字缺漏、疑似重複或對應不明時，保留該框並記錄 ID、原因及「已確認／疑似」，繼續校對同頁可獨立判斷的其他框，保存後保持整頁未完成。只有原圖不可用、整頁無法可靠對應，或使用者明確要求整頁跳過，才跳過整頁；不將疑點直接描述成已確認錯誤。
- 同頁有把握的修改可集中提交；**提交後必須看重新渲染的畫面**，檢查改動框、相鄰區域及整頁關係。第一次修正後若仍貼線或溢出，繼續修到合格，再保存。已驗證且未再受影響的區域不重複截圖；保存狀態與核驗版本一致時，只核對保存回傳即可。
- 只有該頁所有文字區域都完成原圖對照和渲染驗收，且無待確認項，才可標「完成」。有待確認項可依工作台流程保存現況，但保持未完成並記下原因。文字完整性檢查只能作附加核對。
- 使用者要求「只檢測、不修改」時，只做唯讀視覺檢查，不提交補丁、保存新修訂或標完成；使用者要求「暫停」時立即停止操作。批評先前檢查不足，不等於授權恢復修改或繼續翻頁。

## 使用者修字後續作

重新 inspect 最新修訂，將使用者修訂後的文字與穩定 ID 留作本輪基準，再調整排版。核對本輪非 LF 字元是否保留，不按舊基準還原使用者修訂。舊報告保留為歷史紀錄，新增補校結果與最新完成數。

字面的反斜線加 n 需要明確格式修正授權；`prelayout_patch_page` 目前只允許真正換行變更，不能繞過限制。已授權時經正式文字編輯介面轉換，逐項記錄前後文字，再以轉換後基準驗證排版；僅當實際工具清單提供對應能力時才改用專用 WebMCP 工具。

## 每頁請求與用量紀錄

執行時在本機紀錄累計工具呼叫、WebMCP 操作、截圖、重試與補校次數，正常校對、局部待確認、整頁跳過分開統計。一次工具呼叫可以含多個操作與截圖，不混稱為模型請求；保存上一頁並讀取下一頁的合併呼叫歸入下一頁，最後單獨保存歸入當頁。

需要分析 token 時再讀可取得的執行用量紀錄，分列未快取輸入、快取輸入與輸出；無法可靠對應頁面的用量列為共用／未分配。工具呼叫數不換算成 token，不把缺失值當作零，也不為了計數增加瀏覽器請求。原始計數留在本機，對話只回傳摘要；補校另列，避免混入原批次平均。

## 回報必須與實際動作一致

逐頁記錄哪些頁、哪些區域**實際放大看過**，哪些框已修改並在渲染後複查，哪些只看過整頁概覽，及仍待確認的項目。可記 ID、修訂號和文字完整性結果以便追蹤，但不能拿它們代替圖片證據。若時間或畫面條件不足，只回報已完成的部分；不要以「5–37 頁已檢查」概括尚未逐框看清的頁面。
