# 版本与发布策略

本项目把“代码版本”和“AutoDL 镜像版本”分开管理。Git Tag 用于标记经过测试、可以追溯的代码版本；AutoDL 镜像用于交付已经包含 ComfyUI、custom nodes、模型与应用的完整运行环境。两者有关联，但不要求每个 Git Tag 都制作新镜像。

## 基本原则

- 本地是主要开发环境；完成修改和本地测试后才推送 GitHub。
- AutoDL 实例是集成与 GPU 验证环境，不直接作为唯一源码来源。
- 远端必须部署某个明确的 Git commit，不使用无法追溯的临时文件组合。
- 远端测试通过后，给这个确定的 commit 打 Git Tag。
- 只有形成有意义的用户交付内容，或运行环境发生变化时，才制作新的 AutoDL 镜像。
- Git Tag 本身不会更新已经创建的 AutoDL 实例。没有独立应用升级机制时，正式镜像可以合理地落后于 GitHub 代码版本。

## 标准开发流程

```text
本地开发
  ↓
本地 lint／build／后端测试／固定样例测试
  ↓
提交并推送 GitHub main
  ↓
把明确的 commit 部署到 AutoDL 测试实例
  ↓
按改动风险做无卡或 GPU 集成测试
  ↓
测试不通过：回本地修改并重复以上流程
  ↓
测试通过：打 Git Tag 并推送
  ↓
判断是否达到 AutoDL 镜像发布条件
```

不要在远端测试实例直接完成长期保留的代码修改。紧急排障若必须临时修改，应尽快把同一修改带回本地仓库、重新测试并提交，避免 GitHub 与镜像内容分叉。

## Git Tag 规则

代码 Tag 使用不带 `v` 的语义版本：

```text
0.1.0
0.1.1
0.2.0
1.0.0
```

- Patch，例如 `0.1.1`：问题修复、兼容调整、小型界面优化。
- Minor，例如 `0.2.0`：新增 Mask 生成、结果挑选、任务管理等向后兼容功能。
- Major，例如 `1.0.0`：正式稳定版或存在明显不兼容变更。

Tag 应使用 annotated tag，说明主要内容和验证范围，并指向已经通过远端测试的准确 commit。不要为每个普通提交打 Tag；Tag 表示一个可识别、可回退、可供镜像选择的稳定节点。

打 Tag 前确认：

1. 工作树干净，目标 commit 已推送至 `main`。
2. `config/runtime.json` 的 `app_version` 与准备发布的 Tag 一致。
3. 前端 lint 和 build 通过，后端测试通过。
4. 需要远端验证的改动已完成对应测试。
5. 仓库不含 Token、私钥、用户图片、生成结果、日志或模型权重。

标准命令：

```bash
git tag -a 0.2.0 -m "0.2.0：版本摘要"
git push origin main
git push origin 0.2.0
```

不要移动或覆盖已经公开的 Tag。发布后发现问题时，修复并创建新的 Patch Tag。

## 是否需要远端 GPU 测试

| 改动类型 | 本地验证 | 远端验证 |
|---|---|---|
| 文案、颜色、静态排版 | lint + build | 6008 页面检查即可，可无卡 |
| 普通前端交互、历史列表、下载提示 | lint + build + API mock/测试 | 6008 集成检查，通常不需要 GPU |
| FastAPI 接口、任务恢复、打包逻辑 | 后端测试 + 集成测试 | 远端小批次，确认持久化和下载 |
| 项目修订／不可变快照、完整封存／删除 | 版本冲突、移目录重开、路径／哈希／引用检查、活动任务与下载互斥 | 6008 集成验证，确认旧 jobs 兼容；快照输入边界另做受影响 GPU 回归 |
| Canvas 编辑与局部合成 | 原尺寸坐标、撤销／保存、来源分配、确认与导出一致性 | 真浏览器操作及服务器保存后羽化预览；不以模拟候选替代模型验收 |
| RF／MangaLens 与共享 GPU gate | CPU 分类、edited 保护、缺模型隔离、取消／重启进程互斥 | 两模型真实 CUDA、小批次与 ComfyUI 双向切换显存验证 |
| Mask 生成、二值化、方向或配对 | 固定样例与边界测试 | 必须跑受影响工作流的 GPU 小批次 |
| 生成图片发现、命名、挑选或归档 | 固定目录样例 + 打包测试 | 必须跑受影响工作流并核对结果数量 |
| 批次器、RGBA、Crop/Stitch | 单元与集成测试 | 必须做真实 GPU 回归 |
| 工作流、模型、custom node、ComfyUI、PyTorch/CUDA | 能做的静态校验 | 必须做三工作流 GPU 回归 |

Mask 与输出挑选虽然不一定修改工作流 JSON，但位于推理输入和结果完整性边界，按高风险应用逻辑处理。Mask 测试至少覆盖尺寸一致、黑白方向、全黑、全白、透明输入、多图 stem 配对和重新选择覆盖；输出挑选至少覆盖多候选结果、stem 对应、缺图、重复输出、用户选择与最终 ZIP/PDF。

## 项目工作台的新增验收项

- 首页可新建、重开与重命名项目；每项目包含原图；已有 Mask 能跳过第一部分直接提交，不要求安装检测模型。
- 页面保存保留完整颜色、other 和 edited；过期请求不覆盖新修订，重开后与保存一致。提交使用不可变 snapshot，后续编辑不改变已提交结果依据。
- 全黑整批不等待 ComfyUI、不载入修复模型，沿用当次底图且所有选中工作流齐页；不生成空比较 PDF。
- 检测 Python 与 Web／ComfyUI 环境分离；缺权重仅停用检测。逐阶段进程退出后才切换模型；取消和服务重启不能提前释放仍在使用的 GPU。
- 第三部分只接完成 run，以其快照比较候选；保存像素来源分配、羽化和逐页确认。画布即时来源预览与保存后的羽化预览要分别验证，成品必须匹配服务器预览。
- 完整项目封存可移到另一数据根目录导入并续编，不依赖原服务器绝对路径，不恢复 GPU 任务。只导出成品、完整项目包及第二部分候选包是不同输出。
- 删除只能作用于明确归属项目的资产和 jobs；活动任务／下载时拒绝，保留旧版独立 jobs 及模型。首页“旧版批次与历史”仍能读取和下载原任务。

运行时依赖有变化时按本文件流程安排新 GPU smoke test 和受影响小批次；第二部分已被用户确认可用，不把重复原基线验收作为本地开发前置，也不能跳过本次新增的快照、Mask 与 GPU 切换边界。

## AutoDL 镜像发布条件

不是每个代码 Tag 都需要新镜像。以下改动可以积累到下一个有意义的镜像版本：

- 文案、颜色和小型布局调整；
- 不影响推理与数据结构的普通网页功能；
- 文档与开发规范；
- 仅供后续开发使用、尚未准备交付普通用户的功能。

以下情况应当制作新镜像：

- Mask 生成或结果挑选已经形成准备交付用户的完整功能；
- 修复会影响普通用户正确性、启动或任务安全的重要问题；
- 改动输入转换、Mask 方向、Qwen RGBA、批次器或结果结构；
- 新增或改变 Python、前端、系统依赖；
- 修改 ComfyUI、custom nodes、模型、LoRA 或工作流参数；
- 积累了一批用户可感知功能，准备形成新的发布里程碑。

因此，是否发布镜像既看技术依赖，也看是否准备把这批功能交付给普通用户。小代码也可能是必须发镜像的关键修复；大量内部文档改动则不需要镜像。

## 镜像发布流程

1. 选择一个已通过远端测试的 Git Tag，记录 Tag 和完整 commit hash。
2. 确认测试实例运行的应用文件确实来自该 commit。
3. 运行与改动匹配的 GPU 回归；运行环境变化时执行完整三工作流回归。
4. 验证 6006、6008、自动启动、任务恢复、结果 ZIP 和 PDF。
5. 确认没有活动修复、检测、封存或下载，重要项目及测试结果已取回；`active_job_id` 与 `gpu_owner` 均为空。
6. 先执行 `./deploy/prepublish-clean.sh` 只读预览并检查每个目标；清单必须覆盖 `COMIC_DATA_ROOT/projects` 和 `jobs`，不能遗漏原图、编辑修订、快照、检测缓存及项目封存。
7. 明确确认后执行 `./deploy/prepublish-clean.sh --apply`。
8. 执行 `deploy/verify.py`，核对 ComfyUI、节点、工作流、模型与前端构建。
9. 再次确认镜像中没有凭据、用户项目及封存、生成结果、运行日志和 Shell 历史；不可直接复制包含数据目录的本地工作树作为公开镜像内容。
10. 在 AutoDL 控制台保存新镜像，记录镜像版本与 Git Tag 的对应关系。

建议每次镜像发布记录：

```text
AutoDL 镜像版本：
Git Tag：
Git commit：
发布日期：
GPU 与显存：
ComfyUI／Python／PyTorch／CUDA：
custom node 版本：
模型与工作流校验：
检测 Python／CUDA／依赖例外及权重校验（若启用第一部分）：
项目／快照／封存格式与旧 jobs 兼容：
回归批次与结果：
已知问题：
```

## 应用版本与镜像版本

当前阶段使用 Git Tag 表示应用代码版本，例如 `0.1.0`。AutoDL 镜像在平台上单独编号，并在发布记录中写明它包含的 Git Tag，不强制复用同一版本号。

未来若增加独立应用升级器，可以进一步拆成：

```text
App 0.3.0
Image Runtime 1.1.0
```

应用更新只替换 React、FastAPI 和普通编排代码，并只重启 6008；运行时镜像继续固定 ComfyUI、节点、模型和 GPU 环境。在升级器完成之前，不允许启动脚本自动拉取 GitHub `main` 或 `latest`，以免公开镜像在无人验证的情况下改变行为。
